# План интеграции КРЯКтики с Табрикой

**Выбранное хранилище:** Табрика, российская облачная база с REST API.  
**Режим кода:** `PORTAL_STORAGE=tabrica`.  
**Статус:** адаптер подготовлен и протестирован на имитации ответов API; проверка на реальном аккаунте обязательна до пилота, потому что токен и ID таблиц ещё не предоставлены. Письменный ответ Табрики от 20.11.2026 проверен и учтён; исходный EML подтверждает доставку вложения с аутентифицированной учётной записи `hello@tabrica.ru`. PDF не содержит проверяемой электронной подписи, а оферта и поручение ещё не акцептованы.

## Ограничения бесплатного тарифа

На официальной странице на дату проверки указаны: 500 записей, 1 000 Public API-запросов в месяц, 50 МБ файлов, 500 МБ трафика и 3 участника. Тариф бесплатен бессрочно, но не является безлимитным.

## Архитектура

Браузер не обращается к Табрике напрямую. Поток:

`браузер → российский сервер КРЯКтики → HTTPS API Табрики → база в РФ`.

Bearer-токен Табрики хранится только в окружении серверного приложения. Встраивать токен в JavaScript или Git запрещено. Табрика заменяет базу, но не заменяет сервер авторизации: пароль проверяется и сессия создаётся сервером КРЯКтики.

## Подтверждённая инфраструктура Табрики

По письменному ответу от 20.11.2026:

- основная база, журнал аудита и история Public API — Timeweb Cloud, ЦОД в Москве;
- файлы и резервные копии — Yandex Cloud, регион `ru-central1`, ЦОД в РФ;
- копия резервных копий — Selectel, ЦОД в Санкт-Петербурге;
- точные адреса площадок в ответе не указаны;
- содержимое таблиц, файлы, резервные копии и журналы за пределы РФ не копируются;
- данные аккаунтов Табрики и содержание обязательных служебных писем передаются сервису Brevo во Франции. Данные из записей таблиц Brevo не передаются.

Полный разбор и реквизиты зафиксированы в `11-проверка-ответа-табрики-20-11-2026.md`.

## Создание базы

После регистрации в Табрике создать организацию и одну базу `КРЯКтика`, затем три таблицы. Имена полей должны совпадать точно.

### Таблица `users`

| Поле | Тип |
|---|---|
| email | email или текст |
| password_hash | текст |
| password_salt | текст |
| first_name | текст |
| last_name | текст |
| region | текст |
| role | текст |
| consent_at | дата/время или текст ISO 8601 |
| consent_version | текст |
| created_at | дата/время или текст ISO 8601 |
| updated_at | дата/время или текст ISO 8601 |

### Таблица `sessions`

| Поле | Тип |
|---|---|
| user_id | число |
| token_hash | текст |
| expires_at | число |
| created_at | дата/время или текст |

### Таблица `applications`

| Поле | Тип |
|---|---|

| user_id | число |
| service_type | текст |

| status | текст |

## API-токен

В настройках организации → API создать отдельный токен с правами чтения и записи только для этой интеграции. Токен нельзя отправлять в чат. Его следует добавить непосредственно в секреты российского сервера.

Из URL интерфейса скопировать числовые ID базы и таблиц и установить:

```text
PORTAL_STORAGE=tabrica
TABRICA_API_TOKEN=...
TABRICA_DATABASE_ID=...
TABRICA_USERS_TABLE_ID=...
TABRICA_SESSIONS_TABLE_ID=...
TABRICA_APPLICATIONS_TABLE_ID=...
```

## Правовые шаги до реальных данных

1. Определить сторону, от имени которой будет акцептована оферта: Роман Бугаенко как физическое лицо либо Движение без образования юридического лица.
2. Оценить и до начала использования урегулировать трансграничную передачу данных аккаунта Табрики и сервисных сообщений через Brevo во Франции; без этого аккаунт с реальными персональными данными не использовать.
3. Акцептовать актуальные редакции оферты и соглашения о поручении обработки ПДн и сохранить подтверждение акцепта.
4. Исходное письмо с техническими заголовками сохранено и подтверждает `auth=pass` для `hello@tabrica.ru`; если требуется формально подписанный документ, запросить проверяемую электронную подпись либо повторную отправку с адреса для юридически значимых сообщений `combitoo@mail.ru`.
5. При необходимости получить точные адреса площадок; ответ подтверждает города и российские регионы размещения, но не содержит адреса московского ЦОДа.
6. Внести Табрику и подтверждённую инфраструктуру в публичную Политику и реестр обработки.
7. Указать подтверждённые сведения в уведомлении Роскомнадзора, не заявляя безусловное отсутствие трансграничной передачи.
8. Адрес оператора заполнен; сверить его с документом, удостоверяющим личность, и подать уведомление до запуска.

## Сервер приложения всё равно необходим

GitHub Pages не может безопасно хранить Bearer-токен и выполнять серверную проверку паролей. Нужен небольшой сервер приложения в РФ. До его выбора интеграция может тестироваться только локально с тестовыми данными.

## Контроль лимита

Каждая учётная запись, сессия и обращение занимает отдельную запись. Бесплатные 500 записей могут быстро закончиться. Сессии нужно регулярно удалять после истечения 30 дней. Перед достижением 80% лимита регистрация должна быть приостановлена или хранилище переведено на другой тариф/сервер.

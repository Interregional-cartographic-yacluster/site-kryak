# Развёртывание КРЯКтики и хранение данных в России

## Выбранное хранилище

Для рабочего пилота выбрана **Табрика** — российская облачная база с REST API. Сервер портала поддерживает её через `PORTAL_STORAGE=tabrica`. Бесплатный тариф ограничен числом записей и API-запросов; подробная схема находится в `documents/personal-data/08-план-интеграции-табрика.md`.

Для локальной разработки сохраняется **SQLite**: она бесплатна, не требует отдельного сервиса и хранится в `data/portal.db`. Файл базы, журналы SQLite и `.env` исключены из Git.

Сравнение проверенных бесплатных вариантов находится в `documents/personal-data/00-бесплатное-размещение-в-рф.md`. Подтверждённого облачного тарифа одновременно безлимитного, бессрочного и бесплатного не найдено.

## Важное ограничение

GitHub Pages может публиковать только статические файлы. Он не запускает `server.py` и не должен использоваться как место хранения персональных данных пользователей портала.

Для рабочего запуска сервер приложения, резервные копии, журналы и база данных должны физически находиться в дата-центре на территории Российской Федерации. Код сам по себе не подтверждает юридическое соответствие: необходимо проверить договор с хостингом, фактическую локацию серверов, процессы обработки данных и документы оператора.

В production сервер не запустится без явного подтверждения территории:

```bash
APP_ENV=production \
DATA_RESIDENCY_CONFIRMED=RU \
RKN_NOTIFICATION_FILED=1 \
PD_DOCUMENTS_APPROVED=1 \
PROCESSOR_TERMS_CONFIRMED=1 \
PORTAL_DATA_PROCESSING_ENABLED=1 \
COOKIE_SECURE=1 \
HOST=0.0.0.0 \
PORT=8000 \
python3 server.py
```

Устанавливать `DATA_RESIDENCY_CONFIRMED=RU` можно только после проверки, что сервер и диски находятся в России. Адрес оператора заполнен. Ответ Табрики от 20.11.2026 подтверждает размещение основной базы, журналов, файлов и резервных копий в РФ; исходный EML подтверждает доставку вложения с аутентифицированной учётной записи `hello@tabrica.ru`, но сам PDF не содержит проверяемой электронной подписи. Обязательные сервисные письма аккаунтов Табрики обрабатываются Brevo во Франции. Для production также необходимо установить `RKN_NOTIFICATION_FILED=1`, `PD_DOCUMENTS_APPROVED=1` и `PROCESSOR_TERMS_CONFIRMED=1`, но только после фактической подачи уведомления, утверждения документов, акцепта условий обработчиков, урегулирования трансграничной передачи и подтверждения российских мест хранения сервера приложения. Переменная `PORTAL_DATA_PROCESSING_ENABLED=1` отдельно включает API регистрации, входа и обращений; по умолчанию они возвращают HTTP 503 и персональные данные не принимаются.

## Локальный запуск

Требуется Python 3.11 или новее. Сторонние пакеты не нужны.

```bash
python3 server.py
```

Откройте <http://localhost:8000/портал/главная>. В этом режиме API обработки персональных данных отключён. Для локальных тестов только с вымышленными данными запустите `PORTAL_DATA_PROCESSING_ENABLED=1 python3 server.py`.

## Что хранится

- учётная запись: email, имя, фамилия, регион и роль;
- криптографический хеш пароля с индивидуальной солью; пароль в открытом виде не хранится;
- дата согласия на обработку персональных данных;
- серверные сессии;
- обращения пользователя и история их статуса.

## Защита

- пароль хешируется `scrypt`;
- идентификатор сессии хранится в cookie `HttpOnly`, `SameSite=Lax`, а в production — `Secure`;
- выдача данных ограничена текущим пользователем;
- база и секреты не публикуются в Git;
- production-запуск блокируется без флага российской территории;
- включены защитные HTTP-заголовки и ограничение частоты попыток входа.

Перед приёмом реальных данных дополнительно необходимы TLS-сертификат, резервное копирование внутри РФ, политика обработки персональных данных, назначение ответственных лиц, регламент удаления данных и оценка требований Федерального закона № 152-ФЗ. Этот файл является технической памяткой, а не юридическим заключением.

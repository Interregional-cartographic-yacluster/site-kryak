# Развёртывание статического сайта КРЯК и КРЯКтики

## Принятое решение

КРЯКтика публикуется исключительно как интерактивный демонстрационный макет без получения персональных данных от посетителей. Регистрация, авторизация, личные кабинеты реальных пользователей, отправка обращений, загрузка файлов, API записи, база данных и cookie приложения удалены.

В проекте больше нет подключения к Табрике или другому облачному хранилищу. Переменной окружения, способной включить обработку, не существует.

## Основное размещение

Сайт предназначен для публикации через GitHub Pages как набор статических файлов. Workflow `.github/workflows/deploy-pages.yml` публикует содержимое репозитория и формирует статические маршруты КРЯКтики.

При таком размещении МХ «КРЯК» не получает через сайт формы, аккаунты, обращения или журналы посетителей. GitHub может самостоятельно обрабатывать технические сведения запросов в соответствии со своими условиями; приложение КРЯК не получает к ним доступа.

## Локальный просмотр

Требуется Python 3.11 или новее. Сторонние пакеты и база данных не нужны.

```bash
python3 server.py
```

Сайт будет доступен по адресу <http://localhost:8000>, КРЯКтика — по адресу <http://localhost:8000/портал/главная>.

Локальный сервер:

- обслуживает только статические файлы;
- не создаёт cookie;
- не сохраняет IP-адреса и пути запросов в журнал приложения;
- возвращает HTTP 410 для любого `/api/*`;
- отклоняет POST, PUT, PATCH и DELETE с HTTP 405;
- не обслуживает `.git`, `.env`, каталог `data` и внутренний каталог `documents`.

## Обязательные ограничения

1. Не добавлять формы, которые отправляют сведения на сервер или стороннюю площадку.
2. Не подключать аналитику, рекламные пиксели, системы обратной связи и внешние формы без отдельной предварительной оценки.
3. Не публиковать email для приёма заявлений, документов или иных сведений о людях.
4. Не добавлять регистрацию, авторизацию, cookie сессий, API или базу данных в текущую статическую архитектуру.
5. Если обработка персональных данных когда-либо понадобится, разрабатывать её как отдельный проект и выполнять правовые и организационные требования до запуска, а не после него.

Это техническая памятка, а не юридическое заключение.
